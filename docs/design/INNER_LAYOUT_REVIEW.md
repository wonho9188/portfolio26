# 서브 페이지와 글 상세 레이아웃 검토 · 2026-11-16

## 적용 기준

홈에서 정한 읽기 쉬운 글자 크기, 공간의 단계, 제목과 설명의 대비를 서브 페이지에도 적용합니다. 모든 간격을 같은 비율로 늘리지 않고 페이지 진입, 섹션 전환, 내용 묶음, 문단을 구분합니다. 원래 문구·프로젝트·글 데이터와 공개 상태는 유지합니다.

## 화면 전체의 흐름

- 작업 페이지는 소개 → 빠른 섹션 이동 → 작업 카드 → 제작 과정으로 이어집니다. 이미지가 있는 구간과 텍스트가 많은 과정을 분리합니다.
- 사이드 작업은 프로젝트 기록 → 작은 실험 → 관련 기술 글 순서로 구분합니다. 모든 기록을 남기되 프로젝트마다 제목이 먼저 읽히게 합니다.
- 유틸리티는 역할의 핵심 설명을 먼저 읽고 세부 역량을 살펴보게 합니다. 본문보다 적용 사례나 분류가 강하게 보이지 않도록 명도를 조정합니다.
- 글 목록은 페이지 소개 → 주제 선택 → 주제 제목 → 글 목록 순서입니다. 빈 주제도 같은 순서를 유지하되 내용량에 맞게 높이가 결정됩니다.
- 글 상세는 제목 → 요약·작성 상태 → 목차 → 본문 → 이전·다음 글 순서입니다. 본문은 높은 대비를 유지하고 요약과 부수 정보만 차분하게 처리합니다.

## 구현과 검증 범위

실제 구현은 `src/styles/pages.css`와 해당 파일을 불러오는 `src/main.tsx`입니다. `.inner-page`와 `.article-page` 계열에 적용해 홈의 여백과 배치를 유지합니다.

분리된 Chromium에서 작업·목록 페이지와 기존 글 상세 16개의 배치를 확인합니다. 화면 폭 320·375·768·1024·1200·1440px 및 대표 PC·모바일의 라이트·다크 화면에서 가로 넘침, 제목 잘림, 실행 오류를 검사합니다. 비교 캡처와 결과는 추적하지 않는 `artifacts/inner-flow-*`에 저장합니다. 기존 메뉴·탭·새로고침·글 연결·테마·스크롤 헤더 검사를 함께 실행합니다. 실제 기기나 사용자 대상 사용성 연구를 수행한 것은 아닙니다.
