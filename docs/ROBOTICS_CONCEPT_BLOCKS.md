# 차곡차곡, 로보틱스 개념 블록

작은 개념을 하나씩 이해하고, 블록처럼 연결해 로봇이라는 큰 구조를 알아가는 기술 블로그 연재입니다. 독자의 나이를 제한하지 않고, 한 번에 이해할 수 있는 정보 단위를 기준으로 글을 나눕니다.

## 글을 추가하는 방법

1. `docs/examples/robotics-post.json`의 작성 틀을 복사합니다. 작성 틀 자체는 공개 목록에 포함되지 않습니다.
2. 고유한 `slug`, 제목, 요약과 본문을 작성합니다.
3. `src/data/posts-source.json`의 `posts` 배열에 추가합니다.
4. 저장소에 반영하면 GitHub Actions가 검사·빌드·배포합니다.

별도의 웹 관리자 편집 화면은 없습니다. 대화에서 글 작성을 요청하거나 저장소의 글 파일을 수정하는 현재 방식을 사용합니다.

FMS 입문 글은 로봇 A(배터리70%, 픽업지2m), B(충전 중15%, 1m), C(다른 작업 중60%, 3m)의 가상 배차 예시입니다. 대기 중·배터리30% 이상 중 최단 거리라는 단순 규칙을 사용하며, 30%는 실제 운영 표준이 아닌 교육용 가정입니다. A의 가용성과 B의 충전 완료를 바꾸면 후보/대기 상태가 달라집니다. 조건 변경은 요청을 초기화하고 배정·완료는 브라우저 내부 상태만 바꿉니다. 실제 FMS나 로봇에 연결하지 않습니다. Robotnik과 MiR의 공식 소개를 바탕으로 업무 배정·상태 확인·주행 시스템과의 관계를 설명합니다.

Task Planning 입문 글은 컵을 탁자에서 선반으로 옮기는 작업을 예로 사용합니다. 탁자 위의 컵은 집기→이동→놓기, 이미 들고 있는 컵은 이동→놓기로 비교하며 단계별 상태를 SVG에 표시합니다. 실제 플래너나 로봇을 실행하지 않는 미리 정한 두 계획이며, 작업 계획과 움직임 계획, 계획과 실행의 역할을 구분합니다. PlanSys2 공식 설명을 참고했습니다.

MuJoCo 입문 글은 중력 유무와 시간을 바꾸는 공 놓기 그림을 포함합니다. 공의 초기 아래쪽 높이는 1.5m, 초기 속도는 0이며, 중력이 있으면 `h = max(0, 1.5 - 0.5 × 9.81 × t²)`로 계산합니다. 바닥에서 반동 없이 멈추는 JavaScript 설명 예시이며 실제 MuJoCo 엔진 실행 결과가 아님을 표시합니다. 공식 개요를 바탕으로 물리 조건·반복 실험·현실과의 차이를 설명하고 MoveIt 글에 연결합니다.

LLM 입문 글은 요청 2개를 고르고 준비된 답변 조각을 하나씩 펼치는 예시를 포함합니다. 실제 LLM이나 토크나이저를 실행하지 않으며, 설명용 조각과 실제 토큰의 차이를 표시합니다. 학습·대화형 모델의 토큰 생성·답변 오류 가능성을 짧게 설명하고 자연어와 Nav2 글에 연결합니다. IBM과 Microsoft Learn의 공식 설명을 참고했습니다.

자연어 입문 글은 같은 이동 요청의 두 가지 표현과 맥락 없이는 목적지가 불분명한 문장을 비교합니다. 미리 작성한 예시를 선택하는 웹 컴포넌트이며 실제 언어 모델을 호출하지 않습니다. 자연어와 자연어 처리(NLP)를 구분하고, 장소 이름을 지도상의 목표로 바꾸는 단계를 거쳐 Nav2에 연결하는 개념을 소개합니다. IBM의 NLP 설명과 ACL의 모호성 연구를 참고했습니다.

Nav2 입문 글은 목적지 2곳, 장애물 추가·제거, 한 칸씩 이동을 지원하는 격자 그림을 포함합니다. 브라우저 안의 작은 격자 탐색 예이며 Nav2 알고리즘이나 ROS를 실행하지 않습니다. 목적지나 장애물 변경은 출발점에서 다시 시작하며, 공식 Nav2 개념 문서를 참고해 플래너와 컨트롤러 역할을 구분합니다. 실제 로봇의 위치 추정·구동 설정은 이 예시 범위에 포함하지 않습니다.

LiDAR 입문 글은 벽의 거리를 바꾸는 SVG 그림과 왕복 거리 설명을 포함합니다. 펄스 방식의 거리 측정 예를 사용하며, 2D·3D 측정과 ROS 2 노드로 연결합니다. 실제 센서 입력 없이 브라우저에서 동작하며 NOAA·NASA와 ROS 2 공식 자료를 참고했습니다.

ROS 2 입문 글은 센서 → 판단 → 제어의 역할을 선택하는 설명 그림을 포함합니다. 노드 사이의 정보 흐름을 보여주는 웹 예시이며 ROS를 실행하거나 실제 로봇을 제어하지 않습니다. 공식 ROS 2 저장소의 소개와 Jazzy 노드·토픽 문서를 바탕으로 작성했습니다. `sourceLabel`로 글별 공식 문서 링크 이름을 지정할 수 있습니다. 배포는 main 브랜치 업로드 뒤 GitHub Actions의 검사·빌드·Pages 배포 단계로 진행합니다.

## 필드

| 필드          | 설정                                                               |
| ------------- | ------------------------------------------------------------------ |
| `kind`        | `tech`                                                             |
| `group`       | `robotics-concept-blocks`                                          |
| `slug`        | 다른 글과 겹치지 않는 영문·숫자·하이픈 주소                        |
| `seriesOrder` | 읽는 순서. 1, 2, 3처럼 입력합니다.                                 |
| `title`       | 이 글에서 이해할 개념을 드러내는 제목                              |
| `excerpt`     | 다룰 개념과 질문을 짧게 소개                                       |

| `meta`        | 연재 회차 등 실제 정보만 입력                                      |

초안과 작성 예정 글도 기존 사이트 방식대로 목록에 표시됩니다. 완성한 글은 `record`로 변경하면 초안 안내 없이 읽을 수 있습니다. 실제 본문이 없는 완성 글은 등록하지 않습니다.

## 구성 원칙

기술 블로그의 모든 글은 한 번에 소주제 하나씩 보여줍니다. 기존 글 데이터는 유지하고 src/data/lesson-slides.ts에서 소개 문단, 단계 설명, 체험, 정리를 순서대로 펼칩니다. LessonParts는 지정한 설명 묶음만 렌더링하며, 그림과 조작 결과는 해당 체험과 함께 둡니다. Life 글은 기존 연속 본문을 유지합니다.

이전·다음 조작부는 화면 하단에 고정합니다. 첫·마지막 화면의 이동 불가 버튼은 비활성화하고, 이동 후 본문은 위에서 시작하며 키보드 초점은 선택한 방향의 버튼에 유지합니다. 글의 대제목은 유지하고 소제목과 진행 숫자만 바뀝니다. ?screen=N으로 새로고침·직접 접근·브라우저 뒤로 가기를 지원합니다. 모바일 안전 영역과 문서 끝 여백을 확보합니다. 뒤쪽 슬라이드는 제목 영역을 조금 줄여 본문에 여유를 줍니다.

- 한 글에는 중심 개념 하나를 담습니다.
- 개념을 이해하는 데 필요한 설명을 작은 문단으로 나눕니다.
- 일상적인 비유를 썼다면 실제 로봇 원리와 어떻게 대응하는지 연결합니다.
- 끝에서는 이해한 개념이 다른 개념과 어떻게 이어지는지 정리합니다.
- 설명의 크기를 줄이되, 필요한 조건과 정확한 용어를 생략하지 않습니다.

## 본문 강조

- 개념 이름과 꼭 기억할 용어는 굵게 표시합니다. 관계·변화·비교를 나타내는 핵심 구절은 본문 색을 유지하고 테마의 강조색 밑줄을 사용합니다.
- 문단 전체를 굵게 처리하지 않고, 핵심 단어와 짧은 구절을 선택합니다. 강조는 글자 크기나 줄 높이를 바꾸지 않으며 긴 구절은 화면 폭에 따라 자연스럽게 줄바꿈합니다.
- 강조 없는 문단을 기본으로 하고, 꼭 필요한 문단에서만 핵심 용어 한두 개를 굵게 표시합니다. 밑줄은 한 화면에서 최대 한 구절만 예외적으로 사용합니다. 제목·표·결과 숫자로 이미 강조한 내용을 본문에서 반복 강조하지 않습니다.
- 글 데이터의 `sections[].emphasis.strong`과 `sections[].emphasis.underline`에 정확한 원문 구절을 배열로 등록합니다. 같은 섹션의 문단과 단계 설명에 적용됩니다. 원문은 평문으로 유지하며 HTML 문자열을 실행하지 않습니다.
- 예: 기구학 문단의 `strong`은 `정기구학`, `역기구학`이고, `underline`은 `손의 위치와 방향이 어떻게 달라지는지`입니다. 인터랙션 내부 설명도 같은 표시 규칙을 사용합니다.

등록된 글은 이 주제 목록에서 `seriesOrder` 순서로 나타납니다. 상세 글의 목록 복귀와 이전·다음 이동도 같은 연재를 유지합니다.

대제목은 항상 ‘MoveIt이란?’이며, 그림은 전체가 보이도록 유지합니다. 손의 목표에서 실행 요청까지 네 단계는 각각 짧은 슬라이드로 읽습니다. RViz와 코드 호출 예제, 비교 표, 기구학·좌표계·TF 체험과 공식 출처는 삭제하지 않고 해당 슬라이드로 옮겼습니다.

다른 로보틱스 글은 기본 개념 → 조작 예시 → 추가 설명 → 관련 도구와의 관계 순으로 4–5장에 나눕니다. ROS 2는 4장, LiDAR·자연어·LLM·MuJoCo·Task Planning·FMS는 각 5장, Nav2는 4장입니다. 새로운 체험을 연결할 때는 등록 이름과 직접 자식 블록 묶음을 lessonParts에 추가하고, 초기 선택 항목이 있는 예시는 selection도 지정합니다. 내용 단위로 나누며 글자 수로 문장을 자르거나 CSS로 본문을 감추지 않습니다.

## 좌표계·TF 체험의 범위

- 로봇·카메라가 같은 방향을 보는 한 줄 위의 예시입니다. 카메라 앞 30cm + 두 기준 사이 20cm = 로봇 앞 50cm로 설명합니다.
- 같은 상자를 보는 로봇과 카메라의 관점을 나란히 비교합니다. 좌표계는 ‘위치를 말하는 기준’, TF는 ‘서로 다른 좌표계를 연결하는 관계와 변환’으로 구분하고, 각 개념이 답하는 질문을 비교 표로 제공합니다. 두 기준의 방향이 다르면 회전 관계도 반영한다고 설명합니다.
- 이 체험은 기준점 변경과 위치 변환을 설명합니다. 실제 TF의 이동·회전과 시간 정보, 3D 변환 전체를 구현하지는 않습니다. 본문에서 실제 TF는 이동과 회전을 함께 다룬다고 명시합니다.
- 카메라의 인식 결과 → TF로 로봇 기준에 맞춰 변환 → MoveIt의 팔 움직임 계획 순서로 연결합니다.
- 참고: [ROS 2 Jazzy — Tf2](https://docs.ros.org/en/jazzy/Concepts/Intermediate/About-Tf2.html).

## 기구학 실험의 범위

- 위에서 본 평면 회전 관절 세 개와 길이 12 / 10 / 4cm인 링크를 사용합니다. 각도는 이전 링크를 기준으로 하며, 손 방향은 +x축을 기준으로 합니다.
- FK는 관절 각도를 누적해 손의 x·y·방향을 구합니다. IK는 목표 손 방향으로부터 손목 위치를 구하고 2관절 해를 계산한 뒤 마지막 관절로 방향을 맞춥니다.
- IK는 두 자세, 경계에서 한 자세, 또는 해 없음으로 구분합니다. 해가 없으면 목표만 표시하고 팔은 마지막으로 닿았던 자세를 유지합니다.
- 관절 제한과 장애물, 속도·시간·충돌 계산을 생략한 교육용 모델입니다. 실제 MoveIt 실행이나 로봇 제어를 수행하지 않습니다.
- 계산 참고: [University of Illinois — Inverse Kinematics](https://motion.cs.illinois.edu/RoboticSystems/InverseKinematics.html).
